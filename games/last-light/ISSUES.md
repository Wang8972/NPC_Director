# 余灯：问题与修复记录

本记录覆盖实际发现的问题。没有 Unity 编辑器的本机不能给出 Windows 编译、画面或性能通过结论。

## LL-001：旧草案将 AI 降为可选聊天、客户端成为世界真源

**现象：** 早期草稿与用户最终定稿不一致。**根因：** 设计讨论前的接口假设未冻结。**修复：** 旧文件明确标为 superseded；使用 Python 权威世界、真实 v2 默认链、Unity 投影。**验证：** HTTP 禁止提交 world flags，台词 ACK 与行动 complete 分离。**理论：** 单一事实源与命令/事件分离。**预防：** 规范—实现—测试映射及版本化契约。**面试表达：** 先划清谁有权改变世界，才谈多 Agent 的自由表达。

## LL-002：并行批次第二个动作异常会留下半提交

**现象：** 故障注入时第一个动作已写状态，第二个抛错。**根因：** 将同一批次的多个副作用当作独立写入。**修复：** complete 在异常时恢复批次前完整状态，保留可重试预约。**验证：** 并行故障回归检查物品、标志、时间与事件均未半提交。**理论：** 事务原子性、幂等完成。**预防：** 对多副作用路径注入中途异常。**面试表达：** 成功消息和实际提交不是一回事，异常必须回到可重试的边界。

## LL-003：联系、检查、团聚与回报被混为一谈

**现象：** 远处检查完孩子，父亲的委托会被全局标志自动标为兑现。**根因：** 使用世界事实代替角色已收到的信息。**修复：** 到期检查父亲自己的认知；实际回报或团聚后才兑现，过期可重新协商。**验证：** 检查发生05、父亲留07时仍要求回报。**理论：** 世界真相、角色信念与消息送达分离。**预防：** 所有人物知识必须有来源与实际受众。**面试表达：** 系统知道一件事，不代表 NPC 已经知道。

## LL-004：结束救援时自动补齐远处成人

**现象：** 早期结算将全部成人拉到终点。**根因：** 将最终确认误当作全队隐式转移。**修复：** 增加明确集合和成人移动动作；结束只结算实际位置。**验证：** 遗漏检修间陈默会得到代价结局，并保持其实际位置。**理论：** 目标判定基于环境事实，而非叙事意图。**预防：** 对每个成功条件做负例。**面试表达：** 好结局必须由之前的操作挣来，不能由最后按钮补出来。

## LL-005：电源与工具出现视觉副本，清推车被画成开门

**现象：** 中文 carrying 标签与英文判断不匹配；已接电源仍在手中；cleared 被当成 open。**根因：** 视觉层使用文本猜测和粗粒度状态。**修复：** 稳定物品ID、真实连接/持有人投影、明确状态枚举，清障和释放门体分别表现。**验证：** 规则与 CPU 几何检查已做；Windows动画/碰撞仍需实机。**理论：** 表现是权威状态的投影。**预防：** 不用台词或模糊字符串猜测物理结果。**面试表达：** 数据正确还不够，玩家看到的物体必须与数据一一对应。

## LL-006：输入锁中断动作移动、受助者只在结算后换位置

**现象：** UI 每帧锁输入时清掉玩家的任务目的地；搬运只驱动助手。**根因：** 用户输入移动与任务演出移动共用取消路径，忽略受助者。**修复：** 演出中的目的地不被输入锁覆盖；母亲、小满、担架和随身设备加入同行表现；半批次不提前完成转移。**验证：** C#语法、几何Mock及专用Windows动作帧夹具；实机结果待用户执行。**理论：** 控制权分层与生命周期。**预防：** 分离输入、任务、视觉和提交。**面试表达：** 禁止玩家输入不应取消已经授权的动作。

## LL-007：公开角色名册提前泄露父亲身份

**现象：** NPC Director 的静态 public_view 包含“小满的父亲”和照看孩子能力。**根因：** 作者人物卡中的公开字段不等于当前观察者已经知道。**修复：** 依据当前角色知识生成公开身份和安全能力列表。**验证：** 林岚初始名册中周屿仅为乘客，不含孩子信息。**理论：** 授权可见与实际知情是两层。**预防：** 检查角色卡、地图、UI和名册所有旁路。**面试表达：** 私密信息经常从辅助元数据泄漏，而非正面回答。

## LL-008：廉价模型的隐藏推理占满输出上限

**现象：** 小协议通过，但规划、演出及证据解释节点出现达到输出上限后结构校验失败。**根因：** Qwen 的隐藏推理占用 max_output_tokens，复杂上下文也有重复。**修复：** 验证并使用 Qwen reasoning=none；压缩重复元数据和schema注释，保留真实属性与机器约束；演出限单个手势/表情；输出预算按节点设置。**验证：** 真实回应与动作闭环在许宁场景通过；其余失败、限额和未覆盖内容完整保存在真实报告中，不能声称全通过。**理论：** 模型单价、token数量、节点数与可靠性需分别测量。**预防：** 先小探测，逐场景记账，不自动升级昂贵模型。**面试表达：** 便宜模型并不自动等于低成本完整链路，需要同时优化上下文和编排开销。

## LL-009：压缩schema时误删同名业务字段

**现象：** 递归删除title/description注释可能连properties中的同名字段一起删掉。**根因：** 未区分JSON Schema关键字和业务属性映射。**修复：** 在properties/$defs等映射层保留键，只移除元注释。**验证：** 比较TurnAnalysis、TrainMeaning、ContentCandidate全部机器约束及真实title字段。**理论：** 结构化转换必须保持语义等价。**预防：** 对schema变换做结构不变量测试。**面试表达：** 优化token不能牺牲协议的精确性。

## LL-010：本机端口已被其他服务占用

**现象：** 8765已有node监听。**根因：** 多个本地应用默认端口冲突。**修复：** 不停止原服务，Mock改8766；health增加app_id并由Unity验证身份。**验证：** 新后端在8766返回last-light标识。**理论：** 可达不等于连接到了正确服务。**预防：** 本地协议也需要服务身份和可配置端口。**面试表达：** 自动启动只能管理自己拥有的进程，不能为方便接管其他应用。

## LL-011：模型批准不等于引用权限通过

**现象：** 真实Author生成候选、Reviewer批准，但候选引用canonical fact ID `f`，极小测试策略没有将它列入available_lore_refs，因此确定性门禁拒绝发布。**根因：** 可信资料和可引用来源的策略投影没有对齐。**修复：** 游戏策略按当前NPC已知事实提供canonical材料及授权来源，转述保持claim；不关闭引用门禁。**验证：** 保留真实失败；录制原回包在补齐合法来源的策略下通过真实暂存/发布事务，不计为新的live通过。**理论：** 语义审核与确定性授权互补。**预防：** 正反两种引用策略回归。**面试表达：** 模型觉得合理，仍不代表它有权引用那个来源。

## LL-012：恢复车电不应自动给便携设备供电

**现象：** 早期规则恢复辅助电后直接停止医疗设备耗电，虽然设备仍标为内置电池连接。**根因：** 用全车状态替代具体接线状态。**修复：** 只有实际连接的设备电源决定消耗和指示灯；未接入车电的便携设备继续耗用内置或备用电池。**验证：** 已修复列车供电但便携设备仍内置连接时，继续等待仍真实扣电。**理论：** 资源守恒与状态归属。**预防：** 测试系统恢复不应影响未连接对象。**面试表达：** 修复供电系统不是给所有设备凭空充电。

## LL-013：跨episode救援计划缺少共同父目标

**现象：** 通用episode会生成各自的根目标，游戏的既有救援任务和物理行动ID尚未完整接到叙事计划策略。**根因：** 世界层和通用叙事层之间的适配遗漏。**修复：** 持久登记last_light_rescue，按NPC知情范围授权同源行动ID用于计划定义；物理写入仍只归世界规则。结束后关闭目标并禁止新对话，不额外生成新救援。**验证：** 默认服务/HTTP/录制回归通过；新增适配未宣称整段live重验。**理论：** 明确应用领域与通用Agent运行时的协议边界。**预防：** 不只测试一句话输出，还测试目标、计划和结果的长期对应。**面试表达：** 接上聊天接口不等于接上完整游戏生命周期。

## LL-014：演出字段与播放状态丢失

旧桥仅传首个表情/手势，并将UI完成确认与接收混用。现完整透传可见performance，独立记录ack/started与completed提交；增加无费用回归。原来的单cue提示限制也已取消，新提示允许少量多cue而不要求填满。

## LL-015：视觉结果与物品重复

旧客户端销毁重建物品，并在确认前播放转移。现使用唯一实例注册表与准备—提交—结果流程，取消不撤销提交。切换会话前立即隐藏旧实例，避免延迟Destroy触发重复检测；演出去重使用会话+行动ID。Windows动作接触精度仍待实际验证。

## LL-016：全局可达不等于当前门已开

外路到05可用时，旧表现将06全局可达误当作05/06内门开放。新增真实直接邻接和首个出口投影；门阻挡与门户使用直接连接。担架形态也改读真实展开标志的只读投影，避免展开后被库存held状态折回。相关回归通过。

## LL-017：跨区域完成动作落在旧场景

检查孩子或连接远处设备会真实移动玩家。结果演出现先沿可用出口离开，按权威回执进入实际抵达区域，再播放该处的收尾，不在旧车厢对空气检修。接头检测明确路由仪表表现。Windows运行仍须核对。
