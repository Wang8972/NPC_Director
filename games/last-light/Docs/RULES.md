# 《余灯》权威规则与验证

本文记录 Python 核心实际提供的规则。完整人物与美术基线见 `GAME_SPEC.md`；真实 AI 接入见 `DIRECTOR.md`。45–60 分钟是体验目标，不是已经完成的 Windows 人工计时结果。

## 权威与运行方式

- `WorldEngine` 保存唯一的物理世界；Unity 只发送输入、展示投影与执行演出。
- 真实模式为 `live`。NPC Director 生成语言、社会决定与组合计划，不能直接移动人、生成物品、修好设备或宣告获救。
- `rehearsal` 是明确标识的作者诊断模式。只有列出的主题会产生预设信息与同意；任意自由文本不会被关键词脚本伪装成 AI，也不会改变物理状态。
- 社会决定送达后调用 `apply_decision`；物理行动必须经过 `propose → begin → complete`。玩家仍需明确确认 AI 建议的计划。
- 不存在善恶总分或用好感值跳过事实、安全条件的机制。

## 固定空间与事故

05—06—07 顺序固定，06/07 可步行，检修间从07进入。急停使服务推车卡住05/06内门。周屿去07接水后发现内门被堵，返回寻找工作人员和工具；小满确实在05，由邻座乘客照看。

过热接头、陈默以前的临时处理、遗漏复测与完工签署分别是稳定事实。检查接头只证明现场烧蚀；检修记录和当事人披露才涉及此前过程。陈默的合作不要求先承认历史责任。

主照明熄灭不等于独立辅助支路断电。安全维修需要实际隔离、验证、修复、复测和恢复。撤离可以不修好供电，但需分别确认交通封锁、步道、出口和接应照明。

孩子有两条实际抵达路径：

1. 两人稳定并清除推车，然后释放05/06内门。
2. 先确认交通、路线和07外门，布置步道照明，再从安全步道操作05外侧释放口。

从步道看到05外门不会显示05内部人物、伤情或物品。

## 行动与逻辑时间

观察、移动、读笔记、交谈、等待网络响应不推进时间。工作、搬运、转移、完整通信与主动等待有明示成本。每项成本来自 `content.ACTIONS`，客户端提交的 duration 不被信任。

计划步骤含固定 action ID、actor、target、helpers 和同计划依赖 ID。未知动作、能力不符、重复演员、缺失依赖和循环依赖被拒绝。前提尚未满足的合法步骤保留等待原因，玩家可以补条件后再执行。

执行批次同时预约演员、助手和独占物品。独立任务按共同经过的时间推进；同一人或同一工具不能在同刻干两件事。批次到最早任务完成或危机反应边界暂停，剩余工作量保留。动作在某个推进单位完成时，先结算动作，再计算该单位的新增暴露，因此及时完成的隔离或转移确实有用。

取消释放未完成任务；已清出的过道、真实位置和已耗电量不会回滚。跳过演出仍提交同一个 execution ID。重复完成回执不重复计时或发物品；取消后的执行 ID 不能再完成。批次内部异常会回滚该次提交的完整状态，保留可重试的预约。

## 危机和供电

- 热源未隔离时，行动时间增加热量；隔离停止新增热源，残余烟气逐渐消散，不瞬间消失。
- 烟气出现和加重会产生有明确见证人的事件。只有实际暴露增加许母的暴露记录；关闭隔断并把她转到07能够阻止这条恶化链。
- 许母初始使用24格内置电量。备用电源初始18格、归许宁持有，同一时刻只能连接一个用途。
- 稳定状态和恶化状态的设备需求不同。实际供电中断会先产生可追踪的照护后果；持续失控可能导致失败。安全转移不等于不再需要供电。
- 原借约仍能保障照护时，不因剧情需要强制反悔。新增照护需求、期限或真实剩余电量使保障不足时，产生重新协商或归还请求。
- 请求归还不会自动拔线、把电源传送回来或补回电量。玩家必须实际停止用途、断开、携带、归还。
- 检修间固定电话使用独立线路；先恢复其接口再完成联络，可绕开借用医疗备用电源的争议。

## 四人的硬边界

| 人物 | 规则保存的因果关系 |
| --- | --- |
| 林岚 | 岗位原文、后续失联、现场报告与已核实结果分开；被质疑不删除工具；邻线封锁不代替路线安全。接受的是具体分工，而非把普通乘客自动变成上级。 |
| 周屿 | 最后见到、听见回应、实际检查和团聚是不同事实。委托需要已入库的可执行任务、接受的救援人和回报节点；远处完成检查不等于父亲收到回报。团聚后仍有陪护占用。 |
| 陈默 | 初始知道独立回路设计，不自动知道当前带电和故障位置；诊断、隔离、修复、复测分别结算。可协助救援而不先公开过去，但不能删记录、伪造复测或跳过隔离。 |
| 许宁 | 借约包含用途、接收人、期限和保留电量；同意、交付、连接、请求收回、实际归还分别保存。只有实际照护保障变化才构成相应撤回依据。 |

拒绝用可核验的条件表示，条件补齐后可以重新协商。清门、应急隔离和固定电话提供不依赖单一人物态度的替代途径。

## 认知、受众与存档

`npc_context(npc_id)` 只含该人的事实、见证事件、承诺、现场人物与可讨论行动。转述标记来源，不把一句话升级成已发生的物理事件；出示玩家实际持有的材料保留其证据质量。跨车厢传话必须有实际可用的通信渠道或先走到对方面前。

`player_shareable_facts` 单独提供给输入材料解释器，由真实玩家话语决定是否出示。Director 在生成 NPC 提示前移除此列表，不能把玩家全部笔记直接视为 NPC 已知。

Unity `view()` 使用数组 DTO：只投影当前区域的人与物体，未进入区域不显示内部描述，远处区域不显示实时烟气。人物角色与演练主题不能提前揭示周屿与小满的关系。

仓库文件为带 SHA-256 校验和的版本化 JSON。写入先验证 schema、人物/物品/计划与因果链，在同目录写临时文件、同步后原子替换。上一份不同进度保留为自动备份；重复保存同一状态不会擦掉该备份。损坏、错误 session ID、路径穿越、符号链接及重复 JSON 键被拒绝。

`Repository.restore` 显式恢复上一份自动进度。UI 的手动检查点另由 API 同时保存世界与 Director 数据，避免只回滚物理世界而保留未来记忆。

## 结局和可复现路线

最终按钮只结算真实位置与照护后果，不自动把遗漏的人变成获救。成人需明确集合或转移；孩子、母亲、普通乘客各有实际救援动作。位置在最后检查后变化，需要更新清点。

| 结局 ID | 结算依据 |
| --- | --- |
| `stay_all` | 辅助供电修复并复测、求援得到回执、安全车厢实际集合与清点完整，九人均在接应点且无照护中断伤害。 |
| `evacuate_all` | 交通、路线、出口和照明落实，九人实际到达避险点，照护保持。无需修复接头或解开内门。 |
| `costly` | 已进入结束救援程序，但有明确遗漏的人员或已发生的照护伤害；如实列明代价。 |
| `failed` | 持续未控制的危险或供电中断超过现场可维持条件。 |

完整集成测试从新建世界出发，经明确演练主题取得社会同意，再只使用公开计划接口执行物理动作：

- 留车路线：并行隔离/整理过道/关闭隔断 → 转移许母 → 领取工具和备件、诊断、验证、修理、复测、恢复供电 → 清内门并检查接回小满 → 电话联络 → 清点、集合所有成人和乘客、最后检查 → 接应。
- 外路撤离：控制热源和照护 → 电话回执 → 手电核实步道、开07外门、照明 → 从步道开05外门 → 检查并实际转移孩子，交接陪护 → 领取展开担架、转移许母与其他乘客 → 明确让剩余成人到避险点 → 最后检查、结束撤离。

## 物体表现协议

人物 `carrying` 是稳定物品 ID，不是中文名称；中文标签来自 inventory。物品已连接设备时不再同时表现为手持。`oxygen` 跟随许母的位置；`backup_supply` 根据实际接入设备或持有人位置定位，并保留唯一实体。

| 对象 | state 枚举 |
| --- | --- |
| `tool_rack` | 尚在架上的 `tools,lamp,spares` ID 子集；否则 `empty` |
| `stretcher_rack` | `stored` / `empty` |
| `fixed_phone` | `needs_interface` / `ready` |
| `cable_joint` | `unexamined` / `diagnosed` / `isolated_diagnosed` / `repaired` / `tested` / `powered` |
| `oxygen` | `running_internal` / `running_backup` / `unpowered` |
| `backup_supply` | `held` / `connected_radio` / `connected_medical` / `depleted` |
| `outer_door05` | `closed` / `open`；在 tunnel 的投影只表示外侧释放口 |

## 无付费调用验证

从 `backend` 目录执行 `python -m pytest tests -q`。核心覆盖文件为 `test_engine_routes.py`、`test_engine_invariants.py`、`test_engine_power.py` 和 `test_repository.py`；Director 与调度器另有自己的录制/假传输测试。

验证覆盖两条完整路线、四类结局、母亲预防与条件撤回、物品连接/位置/真实耗电、父亲信息和陪护、隐私投影、并行、取消、重复完成、执行中存档恢复及故障注入后的原子回滚。测试不调用付费模型，也不证明 Unity 画面或 Windows 构建已实测。
